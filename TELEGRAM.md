# Telegram и «Матрица»

Второй канал напоминаний, использующий те же задачи и Supabase Auth. Веб-приложение и Web Push продолжают работать независимо.

## Подключение владельцем

1. В официальном https://t.me/BotFather отправить `/newbot`, выбрать имя и свободный username.
2. В «Матрице» войти в свой аккаунт, открыть колокольчик → Telegram → «Настроить своего бота». Вставить токен в поле пароля и сохранить. Доступ к настройке имеет только владелец проекта, зафиксированный при установке серверной части. При нескольких исходных владельцах настройка автоматически не присваивается первому посетителю.
3. Нажать «Подключить Telegram», перейти по одноразовой ссылке и нажать «Старт». Ссылка действует 10 минут, новая ссылка отменяет прежнюю. Пароли Telegram и Apple не нужны.
4. Вернуться в настройки и нажать «Проверить подключение», затем «Проверить сообщение». Разрешить уведомления Telegram и звук личного чата.

## Что умеет бот

Текстовое сообщение добавляет задачу во «Входящие». Из карточки доступны описание, теги, подзадачи, дата, время, список, квадрант, выполнение и перенос напоминания на 15/30/60 минут либо завтра в 09:00. Для даты можно написать «завтра 09:00», «2026-12-01 14:00» или «-» (без даты). `/cancel` отменяет ввод.

Разделы: `/today`, `/week`, `/inbox`, `/matrix`, `/lists`, `/months`, `/overdue`, `/archive`. Поиск: `/search текст`. Длинные списки разбиты на страницы. В меню есть ссылка на веб-приложение. Удаление задач из бота не предусмотрено. `/disconnect` отключает чат и отменяет Telegram-напоминания, сохраняя все задачи и Web Push.

Напоминания используют стабильный часовой пояс аккаунта. Если он ещё не установлен, его задаёт устройство при привязке. Сканирование — раз в минуту, доставка зависит от доступности сервера, Telegram, сети и настроек телефона. Это не будильник с гарантированным звуком в режиме фокусирования.

## Сервер

Новая функция `matrica-telegram` проверяет JWT пользователя для клиентских действий, секретный заголовок Telegram для webhook и отдельный секрет планировщика для cron. `verify_jwt=false` необходим для Telegram webhook; аутентификация выполняется внутри каждого обработчика.

`supabase/telegram.sql` — аддитивная схема; `supabase/telegram-cron.sql` — отдельное минутное расписание. Существующие `tasks` не переписываются. Новые таблицы имеют RLS и доступны только серверу. Одноразовые ссылки хранятся как SHA-256; токен бота и webhook-секрет — в Supabase Vault. Токен не записывается в браузерное хранилище, исходники или логи. Настройка webhook не удаляет ожидающие обновления Telegram.

Webhook принимает только личный чат с совпадающим отправителем. Каждый запрос задач ограничен `user_id`. Изменения проверяют `updated_at`; выполнение и создание следующего повтора происходят в одной транзакции с тем же детерминированным ID, что в веб-приложении. Повтор Telegram update не создаёт новую задачу. Завершённые updates очищаются через 7 дней; есть ограничение 30 новых действий на чат в минуту.

Очередь Telegram отделена от Web Push. Задачи с новой датой отменяют прежнюю отправку. Завершение отменяет напоминание. Неудачные отправки повторяются до 10 попыток с учётом `retry_after`; блокировка бота отключает чат. Повторные напоминания при редком сбое между принятием сообщения Telegram и сохранением результата возможны: Bot API не предоставляет ключ идемпотентности для `sendMessage`. Точный момент показа баннера сервер подтвердить не может.

Тексты задач передаются Telegram только после привязки аккаунта, при просмотре в боте и отправке напоминаний. Групповые чаты и inline-режим не используются.

## Проверки

`npm test` проверяет ядро, веб-сценарии, офлайн-работу и бота на синтетических данных. Живую доставку нужно отдельно проверить после регистрации бота и нажатия «Старт» в Telegram. Подготовленный код без этих шагов не означает, что уведомления уже включены.
