# Web Push для «Матрицы»

Код находится в ветке проверки. Сам по себе коммит не включает серверную отправку.

## Настройка Supabase

1. Проверить, что `public.tasks.id` и `user_id` имеют тип UUID, а `task_date`, `task_time`, `completed` соответствуют текущему приложению. Сделать резервную копию схемы перед миграцией.
2. Применить `supabase/migrations/202610310001_web_push.sql`. Существующие задачи и заметки миграция не переписывает. Добавляются только таблицы уведомлений и триггер постановки напоминаний.
3. Опубликовать Edge Function `matrica-push` с конфигурацией `supabase/config.toml`. Supabase автоматически предоставляет функции `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. Клиент не получает служебный ключ.
4. При первом запросе функция генерирует VAPID-ключи и токен планировщика внутри сервера. Служебная RPC-функция сохраняет их зашифрованными в Supabase Vault, с защитой от гонки двух первых запросов. Чтение этих ключей разрешено только служебной роли. Ключи не попадают в GitHub или клиент.
5. Разрешённые origin по умолчанию: `https://antonantonov1371-ctrl.github.io`, `http://127.0.0.1:4173`, `http://localhost:4173`. Для другого домена задать секрет функции `ALLOWED_ORIGINS` с точными origin через запятую.
6. Вызвать `GET .../functions/v1/matrica-push?action=config` для первичной настройки. Затем применить `supabase/cron.sql`; ключи и URL уже находятся в Vault. Статус `ready` становится true только после успешного запуска планировщика за последние 3 минуты.
7. Опубликовать HTML, `push-client.js`, `sw.js`, `manifest.webmanifest` и `icons/` в одной директории на HTTPS. Основной URL iPhone не может быть `127.0.0.1`.

## Поведение

- Пользователь включает уведомления кнопкой колокольчика и подтверждает системное разрешение. На iPhone сайт нужно сначала добавить на главный экран.
- Первый подключённый телефон задаёт часовой пояс аккаунта. Он показывается в настройках уведомлений, последующие устройства его не меняют.
- Напоминание создаётся для невыполненной задачи с датой и временем. Изменение времени переносит его, выполнение или удаление отменяет.
- Старые задачи с будущим временем ставятся в расписание при первом подключении устройства. Уведомления за прошедшие дни не рассылаются.
- Сервер проверяет очередь раз в минуту. Сеть, настройки ОС и режим фокусирования могут задержать показ; это Web Push, не будильник.
- Повторные запуски защищены арендой задания и журналом доставок по устройству. Как и у любой внешней доставки, сбой между отправкой и записью результата теоретически допускает повтор; одинаковый tag сворачивает повтор в одно уведомление.
- После выхода из аккаунта подписка устройства отключается, чтобы задачи прошлого аккаунта не приходили следующему пользователю.
- Содержимое уведомления — название задачи. Описание в push не отправляется.

## Приёмка на реальном устройстве

1. Открыть опубликованную HTTPS-версию на iPhone, добавить на главный экран, войти и включить уведомления. Нажать «Проверить уведомление».
2. Задать задаче время через 2–3 минуты, закрыть приложение и дождаться уведомления. Нажатие должно открывать соответствующий день.
3. Перенести время до срабатывания; старое время не должно прислать уведомление. Повторить с выполнением и удалением задачи.
4. Проверить второе устройство, отказ в разрешении и выход из аккаунта. Убедиться, что чужие подписки недоступны через RLS.

Пока сервер не подключён, интерфейс сообщает об этом и не выдаёт неработающие уведомления за включённые.
